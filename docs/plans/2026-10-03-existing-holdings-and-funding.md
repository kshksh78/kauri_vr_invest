# 기존 보유 주식과 반복 증액 지원

2026-10-03 추가 요청을 기존 구현 계획에 덧붙인다. 기존 계획의 seed·회차 스냅샷·가격 기준은 유지한다.

- 신규 매수와 기존 보유 이관을 명시적으로 구분한다.
- 기존 보유는 시작일 평가가격·주수·실제 Pool로 시작 자산을 계산한다. 신규 매수와 초기 매수 수수료를 발생시키지 않는다. 초기 V는 주식 평가액이며 기존 VR의 V를 직접 가져올 수도 있다.
- 시작 이전 취득원가는 선택 참고값으로 저장한다. 과거 손익과 VR 시작 이후 성과를 혼동하지 않도록 시작 자산 기준을 표시한다.
- 반복 증액은 각각 날짜와 금액을 가진 flow 사건으로 저장한다. 같은 회차의 실제 입출금은 합산하며 예정 정기액을 대체한다. 회차 중 입력은 다음 회차에 반영되고, 반영 전·후 상태와 누적 순투입금을 구분한다.
- 백테스트에도 기존 모형 주수와 현금으로 시작하는 입력을 제공한다. 수정종가 모형 주수는 실제 브로커 주수와 구별한다.
- 총자산 차트와 입출금을 제거한 TWR 차트를 선택할 수 있게 한다.

검증 예: 기존 100주·평가가격80·Pool7,000 → 시작 자산15,000, V8,000, 초기 비용0. 두 번의 2,000/3,000 입금은 다음 회차 Pool12,000·V13,700으로 한 번 합산 반영한다. 이후2,500 증액은 다음 회차에 반영한다. 고정 가격·0비용 백테스트에서는 증액 후에도 TWR/MDD가0이다.

구현 순서: 독립 실패 테스트 → 공통 기존 보유 초기화/장부/백테스트/API → 입력 UI와 사례 안내 → 전체 테스트/브라우저 → 중단된 최종 리뷰 복구 → WSL 재배포·GitHub PR 전달. 기존 저장 계좌는 소급 수정하지 않는다.

최종 리뷰에서 대기 입금 표시, 평가액 응답 순서, 계좌 전환 중 장부 응답, 비용률 공란 복원, 휴장 후 실제 회차 시작일 입금, Origin 검증 범위를 확인하고 회귀 테스트와 함께 수정했다. 예약표 40단계·비교 20종목·최근 일별 200행은 개인용 화면 범위로 유지한다. 전체 일별 값은 CSV로 제공하며 이 제한이 잔고 계산이나 전체 백테스트 기간을 줄이지 않는다.

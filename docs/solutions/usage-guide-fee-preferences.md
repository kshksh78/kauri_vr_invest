# 브라우저 비용률 기본값과 확정 회차의 비용을 구분하기

사용자가 편도 0.25%를 확인했지만 새 계좌 화면은 0.05%로 되돌아가 반복 입력이 필요했다. 화면의 새 기본값과 저장 가능한 개인 기본값을 바꾸되, 기존 확정 회차의 비용과 거래 내역까지 자동으로 재해석하면 이미 확정한 Pool과 매수 한도가 달라진다. 따라서 화면의 기본값 변경, 계좌의 미래 기본 설정, 확정 회차 재계산, 거래별 비용률을 별개로 유지한다. 기존 API의 비용 생략 기본값도 보존하고 화면은 비용률을 명시해서 전송한다.

사용 설명 탭과 `/#help`, `/#guide-fees` 등 직접 링크를 추가했다. 초기 투자, 기존 보유, 예약표 한 행의 의미, LOC, 비용률, 옵션, 증액, 회차 진행, 백테스트, 가격 확보를 실제 구현에 맞춰 안내한다. LOC 조건은 Nasdaq 마감 경매 FAQ와 SEC 지정가 안내를 확인했으며, 실제 주문·부분 체결 시뮬레이션과 종가 백테스트의 차이를 명시했다.

사용자가 확인한 편도 0.25%를 화면의 새 기본값으로 사용한다. 비용률 저장은 브라우저 기본값과 새 계좌·백테스트 입력만 바꾼다. 기존 계좌·확정 회차와 거래 내역에는 API 쓰기를 하지 않는다. 기존 API의 생략 기본값 0.05% 및 저장된 회차는 보존한다. 빈 거래 비용률은 해당 회차 값, 명시적 0은 비용 없음이라는 구분도 유지한다.

사용 설명 내용과 스타일은 직접 렌더링으로 확인했다. 재사용·품질 검토에서는 변경이 필요한 문제가 없었다. 효율 검토는 리뷰 슬롯 제한으로 동일 기준을 적용해 직접 수행했으며 추가 네트워크 요청이나 반복 작업이 없음을 확인했다.

## 리뷰와 실제 배포

Compound Engineering 최종 코드 리뷰 `20261003-guide-fee`는 완료되었고 최종 판정은 Ready to merge였다. 저장된 백테스트의 다른 조건 보존, 목차의 해시와 실제 화면 위치 검증, 학습 기록의 위치에 관한 보완 3건을 모두 반영했다. 남은 결함과 미적용 항목은 없다. 별도 제공자 CLI가 없어 교차 모델 검토는 실행하지 않았고 독립 로컬 검토로 대체했다.

`bash scripts/deploy_wsl.sh`로 WSL에 배포했다. 읽기 전용으로 배포 전후 계좌 문서·revision과 가격 데이터를 비교했으며 계좌 4개, 가격 46,047행, snapshot 17개가 동일했다. 새 백업 `vr-20261003T014840670199Z.sqlite3`도 배포 전 DB와 일치하고 SQLite integrity는 `ok`다. `/api/health`는 database ready로 응답했다. 실제 서비스에서 거래나 계좌를 테스트 생성하지 않았다.
